# BMAS Gauge Blocks: CAD

Open DWG and DXF interchange test files

A public set of drawings for testing how CAD programs read and write DWG and DXF, so that drawings move between
programs without losing anything. Anyone may use it to test or improve a CAD program or library.

## Scope of the first release

2D drafting as used for industrial automation schematics and panel layouts. That is expected to cover most common 2D
features. 3D modeling and other domains come in later releases.

## Layers

1. **Intent** (`intent/`). Each test drawing is defined once, independently of any program: its features, the
   invented values, and the expected result of reading it, per the public DXF Reference. Expected values come from the
   intent, never from one program's output. The applicable published DXF Reference or DWG specification governs first. Where published standards
   leave a case unsettled, the intent seeks maximal compatibility using documented application semantics and
   independent read/write evidence. [Autodesk symbol-table semantics](https://help.autodesk.com/cloudhelp/2018/ENU/OARX-DevGuide/files/GUID-83ABF20A-57D4-4AB3-8A49-D91E0F70DBFF.htm)
   supplies name-comparison behavior; the [Open Design Specification](https://static.opendesign.com/files/guestdownloads/OpenDesign_Specification_for_.dwg_files.pdf)
   defines DWG structures. Each field identifies its basis.
2. **Native set** (`native/<program>/`). The same intent built from scratch in each program by that program's
   generator, saved at every format and version it can write. Shows how each program writes the same content; tests
   readers.
3. **Cross set** (`cross/<writer>__<resaver>/`). Each declared source file opened and saved again by its declared re-saver at the
   same format and version. Tests writers. Regenerated automatically and committed, so users do not need every program.
4. **Checker** (`checker/`). Reads any file, extracts the intent's fields, and reports same or differs against the
   intent. DXF is read directly; DWG is read through a named converter, and every result row names the reader used. A
   program's own DWG output is not graded only by that same program's converter.
5. **Results** (`results/`). Measured outcomes per program build, kept apart from the drawings so a project can take
   the drawings without the measurements.

## Identity of every file

- `intent_id`: what the drawing means.
- `representation_id`: which of the acceptable encodings of that meaning the file uses. Where the DXF Reference allows
  more than one way to write the same thing (for example center-justified text), each way gets its own representation
  pointing at the same intent and the same expected result. The first release may carry one representation per intent;
  the field exists from the start.
- A provenance record record per file: program and exact build, format and version, encoding (ASCII or binary DXF), how it was
  made (script and input digest), and the intent and representation ids.
- File names use no spaces or parentheses (some converters fail silently on them).

## Programs

| Program | Role | Notes |
|---|---|---|
| ezdxf (open-source Python library, MIT) | Native writer of every synthetic input; reader and re-saver | Files it generated are marked as ezdxf-based |
| ODA File Converter | Reader, converter and re-saver | A target for smooth opening; structured to support ODA development |
| BricsCAD | Native writer, reader, re-saver | Outputs made by agents; regenerated by one script before publishing |
| CADCraft | Reader and re-saver | Public release or upstream commit only, never local fix builds |
| AutoCAD (LT) | Placeholder columns until available | Includes "opens but loads no drawing", a failure seen with some non-AutoCAD DXF |

Only pinned public program builds appear in the published results.

## Features, in priority order

Drawn content: text and its justifications, multiline text, attributes and attribute definitions, blocks (nested,
rotated, mirrored, scaled), hatches with islands, wipeouts, polylines (lightweight and old-style with widths and
bulges), dimensions, layouts and page setups, draw order, raster images, tables, regions.

Background content (exists in the drawing but is not drawn), which must also survive conversion and saving:
unused block definitions; many layers in mixed states (on, off, frozen, locked, not plotted, per-viewport freeze and
color overrides); loaded but unused linetypes, text styles and dimension styles; named page setups and plot-style
references; empty layouts; registered applications, extended data and extension dictionaries; scale lists; named
views and coordinate systems; groups.

Encodings: DWG and ASCII DXF at 2000, 2004, 2007, 2010, 2013 and 2018; binary DXF where a program writes it; R12 as
input; text in a pre-2007 code page (accented, Cyrillic, East Asian) and 2007+ UTF-8 versus escaped text.

Features only AutoCAD can produce faithfully (AutoCAD dynamic blocks, proxy objects from AutoCAD vertical products)
appear as placeholder rows until AutoCAD is available.

## Regeneration

One script rebuilds the native and cross sets from the generators. Programs write volatile fields (timestamps, file
identifiers, handle seeds), so the checker computes a content digest that ignores them, and a regenerated file is
committed only when its digest or its program build changes.

## Later releases

- More than one representation per intent wherever several are acceptable.
- A generator others can point at their own drawings to produce the full native and cross set from them.

## Derived coverage

Intents state status only for wanted, planned, or blocked requests without drawings. Covered and partial are computed per feature, format, version, and encoding from declared source folders in `programs/pairs.json`, measured declared cross pairs, and `programs/capabilities.json`. Missing runnable pairs are named; impossible outputs do not make a cell partial. Cells for which no declared source folder can receive that format, version, and encoding are no source and do not count against the intent. An intent is covered when all remaining applicable cells are covered.

The [DXF standard inventory](standard/README.md) lists owning Reference pages and
computes dataset coverage from intent selectors and citations, provenance-linked
native ASCII drawing presence, and item-naming future requests. Generator source
witnesses supplement the evidence without deciding status.
